# Onda 6.1 — Piloto: refactor de `app/admin/documentos/page.tsx`

**Data:** 2026-05-19
**PR:** TBD
**Onda:** 6.1 — Quebrar componentes >800 LOC (piloto)

## Contexto

A Onda 6.1 quebra componentes admin/cliente acima de 800 LOC para reduzir blast radius de edições e melhorar testabilidade. Há 10 candidatos identificados; este é o piloto que estabelece o pattern reutilizável para os 9 restantes.

**Componente alvo:** `app/admin/documentos/page.tsx` (819 LOC) — gerenciador admin de documentos com filtros, busca, paginação, ações em lote, export e dialogs.

**Por que este como piloto:**
- Menor entre os candidatos admin-only
- Variedade de UI (stats clicáveis, filtros múltiplos, bulk actions, dialogs) — cobre cenários que aparecerão em outros candidatos
- Admin-only — baixa pressão de UX em caso de regressão visual menor
- Usado diariamente em produção pelo dono do produto, então qualquer regressão é detectada cedo

## Goal

Quebrar `app/admin/documentos/page.tsx` (819 → ~180 LOC) em utilities puras + hook composto + 5 sub-componentes. **Zero mudança comportamental** — mesmo HTML, mesmas chamadas de API, mesmo fluxo. Estabelecer pattern reutilizável.

## Non-goals

- ❌ Migrar filtros para URL state (`useAdminList` faria, mas é mudança comportamental — adiar para PR follow-up dedicada)
- ❌ Substituir `verifyAdmin` por `useAdminAuth()` (semantics diferentes: `location.href` vs `router.push` — paridade não-trivial)
- ❌ Testes de UI/componente/hook (alinhado com o pattern atual do projeto: testes só em `lib/`)
- ❌ Otimizações de performance (refactor não é optimization — phase separada)

## Hook API design

```typescript
// hooks/use-documentos-admin.ts
import type { DocumentData } from '@/components/admin/DocumentCard';

export interface DocumentFilters {
  course: string;
  category: string;
  type: string;
  visibility: string;
  entity: string;
  status: string;
}

export interface UseDocumentosAdminReturn {
  // Loading
  isLoading: boolean;                    // auth check
  isLoadingDocs: boolean;

  // Data
  documents: DocumentData[];             // raw
  filteredDocuments: DocumentData[];     // client-side filtered (derived)
  stats: { total: number; complete: number; warning: number; critical: number };
  serverPagination: { total: number; page: number; pageSize: number; totalPages: number } | null;

  // Filters
  searchTerm: string;
  setSearchTerm: (v: string) => void;
  filters: DocumentFilters;
  setFilter: <K extends keyof DocumentFilters>(key: K, value: DocumentFilters[K]) => void;
  clearFilters: () => void;
  activeFiltersCount: number;

  // Pagination
  currentPage: number;
  setCurrentPage: (n: number) => void;
  itemsPerPage: number;
  totalPages: number;
  totalItems: number;

  // Selection
  selectedDocuments: Set<string>;
  toggleDocumentSelection: (id: string) => void;
  toggleSelectAll: () => void;
  clearSelection: () => void;

  // Bulk
  bulkAction: string;
  setBulkAction: (v: string) => void;
  handleBulkAction: () => Promise<void>;
  isProcessing: boolean;                 // antes `isDeleting`
  showClassifyPanel: boolean;
  setShowClassifyPanel: (b: boolean) => void;

  // Dialogs + single-doc actions
  deleteDialog: {
    open: boolean;
    onOpenChange: (open: boolean) => void;
    onConfirm: () => Promise<void>;
  };
  previewDialog: {
    open: boolean;
    onOpenChange: (open: boolean) => void;
    doc: DocumentData | null;
  };
  handleDeleteClick: (id: string) => void;
  handlePreviewClick: (doc: DocumentData) => void;

  // Refetch
  loadDocuments: (force?: boolean) => Promise<void>;
}

export function useDocumentosAdmin(): UseDocumentosAdminReturn;
```

### Pontos sutis da API

- **`setFilter` unificado** em vez de 6 setters separados → reduz superfície
- **`deleteDialog` / `previewDialog` como objetos** prontos para plugar nos componentes Dialog (encapsula 4 pares de `useState`)
- **`isProcessing`** renomeia `isDeleting` (cobre delete + markReviewed)
- **`hasLoadedRef` / `isFetchingRef`** ficam internos ao hook (não vazam)
- **Decisão: 1 hook composto, não N hooks focados** — estado fortemente acoplado: `filteredDocuments` depende de `documents` + 7 filtros; `toggleSelectAll` depende de `filteredDocuments`; bulk handlers dependem de `selectedDocuments` + `loadDocuments`. Quebrar em 3 hooks geraria props/refs cruzando hooks (pior que coesão num único).

## Test strategy

### TDD em utilities puras (Phase 1, antes do refactor estrutural)

**`lib/admin/document-status.ts`** — 8 cenários:
1. Doc sem `title` → `critical`
2. Doc sem `category` → `critical`
3. `orientacao-normativa` sem `onNumber`/`onYear` → `critical`
4. `enunciados` sem `entityType` → `critical`
5. `sumula` sem `entityType` → `critical`
6. Tags vazias + articles vazios → `warning`
7. Sem `description` (com tags) → `warning`
8. Tudo presente (title, category, tags, description) → `complete`
9. Edge: `tags` em formato CSV vs JSON vs array — `parseArray` cobre os 3

**`lib/admin/document-export.ts`** — testa funções que retornam `{blob, filename, count}`:
1. JSON: shape do objeto, indent 2, filename `documentos-YYYY-MM-DD.json`
2. CSV headers: 7 colunas em PT-BR (`Titulo`, `Descricao`, `Curso`, `Categoria`, `Tipo`, `Publico`, `Data`)
3. CSV escaping: vírgulas e aspas em `description` ficam entre `"..."`
4. CSV course resolution: `courseId` numérico → `course.title`, `isCommon` → "Todos os cursos", vazio → ""
5. Filtragem por seleção: `selectedIds` non-empty filtra; vazio exporta tudo

### Não testar (alinhado com pattern atual)

- Hook composto (zero hook tests no projeto)
- Sub-componentes React (zero component tests no projeto)
- A page em si (zero page tests)

**Justificativa:** adotar testes de hook/componente nesta PR carregaria duas decisões (infra de teste + refactor). Decidir testing infrastructure em PR específica se for desejado, separado da campanha de saneamento.

## Build sequence

5-6 commits na mesma branch `refactor/onda6.1-piloto-documentos`, squash-merged numa PR única:

1. **Spec + plan docs** — este design + plano gerado pela skill `writing-plans`. Build OK.
2. **TDD utilities (Phase 1)** — `lib/admin/document-status.ts` + `lib/admin/document-export.ts` + testes (red → green). Page ainda usa funções inline. `npm test` passa.

4. **Extract hook** — `hooks/use-documentos-admin.ts` com toda a logic de state/effects/handlers. Page consome hook, JSX inline. Page: ~750 → ~480 LOC. Cuidado com ordem dos `useEffect` e `hasLoadedRef`.

6. **Smoke test evidence + PR body** — checklist dos 15 itens + screenshots before/after na PR description.

## Risk register

| Risco | Severidade | Mitigação |
|---|---|---|
| Hook quebra `hasLoadedRef`/`isFetchingRef` semantics (recarrega 2x ao montar) | Média | Manter refs `useRef` no hook, copiar lógica de guards bit-by-bit, smoke test item #1 confirma. |

| `useEffect` order (rules of hooks) | Média | Hook tem 3 useEffects: verifyAdmin (mount), reset hasLoaded on page/category change, load on isLoading/page/category. Mantenho ordem idêntica do original. |

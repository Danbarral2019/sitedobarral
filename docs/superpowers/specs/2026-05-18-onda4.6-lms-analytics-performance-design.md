## Contexto

O LMS (`/admin/lms/analytics`, `/admin/lms/insights`, `/area-restrita/meu-progresso`, e rotas de curso/módulos do aluno) faz queries pesadas com padrões problemáticos: N+1 estrutural, loop quadrático em memória e queries sequenciais sem `Promise.all`. A campanha de saneamento (2026-05, Onda 4) já fechou padronização de API, AI Gateway e otimização de queries `leiArticles` (Onda 4.5, 5x speedup). A Onda 4.6 ataca os hotspots LMS antes que o crescimento da base os converta em incidentes.

2. **Dataset pequeno demais para SQL agg compensar** — Postgres prefere Seq Scan (cabe em ~3 buffers). HashAggregate adiciona overhead em vez de remover.
3. **Não há problema mensurável de performance hoje.** Tudo roda sub-milissegundo.

Isso pivota a Onda 4.6 de "consertar gargalos" para "remover armadilhas estruturais antes do crescimento", com instrumentação para detectar quando os thresholds forem cruzados.

### PR 4.6.1 — Eliminar N+1 estrutural (`getQuizStatsBatch`)

**Arquivos modificados (cutover):**

- `app/api/admin/lms/analytics/route.ts` — substitui linhas 263-287 e 296-303 por chamadas a `getQuizStatsBatch` / `getAttemptScoresByUser`; **adicionalmente** paraleliza as 5 queries iniciais de `getGlobalAnalytics` (linhas 26-79) com `Promise.all` (cobre **H3**)

**Métricas alvo:** redução do count de queries Prisma de ~50 (com 10 quizzes em produção futura) para 1 em cada hotspot. Validado por mock prisma counter no teste integration. Adicionalmente, latência de `getGlobalAnalytics` reduz pela ordem da query mais lenta (em vez da soma de todas).

### PR 4.6.1b — Fix loop quadrático

**Refactor.** Pre-agrega `progress` em estruturas indexadas antes de iterar, transformando O(users × lessons × progress) em O(users + lessons + progress).

**Arquivos novos:**

- `lib/lms/progress-aggregation.ts` (~80 LOC):
  - `groupProgressByUserModule(progress, modules): Map<userId, Map<moduleId, { completed: number; total: number }>>` — uma passada O(N) sobre `progress`, lookup O(1) depois
  - `computeModuleAvgCompletion(grouped, modules): Array<{ moduleId, avgCompletion }>` — soma e divide em uma passada
- `lib/lms/__tests__/progress-aggregation.test.ts` (~100 LOC)

**Arquivos modificados:**

- `app/api/admin/lms/analytics/route.ts` — substitui linhas 230-256 (módulo) e 305-310 (quizScoresByUser) por chamadas aos helpers

**Métricas alvo:** com `users=100, lessons=50, progress=2500`, tempo do bloco reduz de O(125M) operações filter para O(2500) hash lookups (~50000x em pior caso teórico). Hoje, com 78 rows, ganho é imperceptível mas o refactor remove a armadilha.

## Data flow & componentes

### `withTiming` wrapper

```ts
// lib/lms/query-timing.ts
export async function withTiming<T>(label: string, fn: () => Promise<T>): Promise<T> {
  const start = performance.now();
  try {
    const result = await fn();
    const ms = performance.now() - start;
    apiLogger.info({ lms_query: label, ms_total: Math.round(ms) }, 'lms.query');
    if (ms > 500) {
      Sentry.addBreadcrumb({
        category: 'lms.slow',
        level: 'warning',
        message: label,
        data: { ms: Math.round(ms) },
      });
    }
    return result;
  } catch (err) {
    apiLogger.error({ lms_query: label, err }, 'lms.query.failed');
    throw err;
  }
}
```

### `getQuizStatsBatch` (PR 4.6.1)

```ts
// lib/lms/analytics-queries.ts
export interface QuizStats {
  quizId: string;
  totalAttempts: number;
  passedAttempts: number;
  passRate: number;
  avgScore: number;
  uniqueUsers: number;
}

export async function getQuizStatsBatch(quizIds: string[]): Promise<Map<string, QuizStats>> {
  if (quizIds.length === 0) return new Map();

  const attempts = await prisma.quizAttempt.findMany({
    where: { quizId: { in: quizIds } },
    select: { quizId: true, score: true, passed: true, userId: true },
  });

  const byQuiz = new Map<string, QuizStats>();
  for (const id of quizIds) {
    byQuiz.set(id, {
      quizId: id, totalAttempts: 0, passedAttempts: 0,
      passRate: 0, avgScore: 0, uniqueUsers: 0,
    });
  }

  const usersByQuiz = new Map<string, Set<string>>();
  const scoreSumByQuiz = new Map<string, number>();
  for (const a of attempts) {
    const stats = byQuiz.get(a.quizId)!;
    stats.totalAttempts += 1;
    if (a.passed) stats.passedAttempts += 1;
    scoreSumByQuiz.set(a.quizId, (scoreSumByQuiz.get(a.quizId) ?? 0) + a.score);

    const users = usersByQuiz.get(a.quizId) ?? new Set();
    users.add(a.userId);
    usersByQuiz.set(a.quizId, users);
  }

  for (const [id, stats] of byQuiz) {
    if (stats.totalAttempts > 0) {
      stats.avgScore = Math.round((scoreSumByQuiz.get(id) ?? 0) / stats.totalAttempts);
      stats.passRate = Math.round((stats.passedAttempts / stats.totalAttempts) * 100);
    }
    stats.uniqueUsers = usersByQuiz.get(id)?.size ?? 0;
  }

  return byQuiz;
}
```

### `groupProgressByUserModule` (PR 4.6.1b)

```ts
// lib/lms/progress-aggregation.ts
export function groupProgressByUserModule(
  progress: Array<{ userId: string; lessonId: string; status: string }>,
  lessonModuleMap: Map<string, string>,
): Map<string, Map<string, { completed: number; total: number }>> {
  const result = new Map<string, Map<string, { completed: number; total: number }>>();

  for (const p of progress) {
    const moduleId = lessonModuleMap.get(p.lessonId);
    if (!moduleId) continue;

    let userModules = result.get(p.userId);
    if (!userModules) {
      userModules = new Map();
      result.set(p.userId, userModules);
    }

    let bucket = userModules.get(moduleId);
    if (!bucket) {
      bucket = { completed: 0, total: 0 };
      userModules.set(moduleId, bucket);
    }
    bucket.total += 1;
    if (p.status === 'completed') bucket.completed += 1;
  }

  return result;
}
```
